# 通用：搜词 → 提取 → 排序（跨 App）

这是一套适用于大多数内容 App 的通用采集流程：

1. **启动 App**：`pua_launch_app`（或 WDA `/wda/apps/activate`）
2. **进入搜索**：点搜索框 → `pua_type_text` 输入 → 触发搜索
3. **滚动采集**：循环 `pua_swipe` + 取控件树（`/source?format=json`）
4. **结构化提取**：解析 `label` 节点，抽出标题/作者/互动数
5. **去重 + 排序**：按互动量排序输出

## 关键实现点

- **控件树优先**：用 WDA 原生 `/source` 的 `label` 节点，别用会按 `name` 过滤的封装层（会漏报）。详见 [../../docs/accessibility.md](../../docs/accessibility.md)。
- **输入用 WDA 原生注入**：`pua_type_text` 不经系统输入法，**无拼音候选吞字**问题。
- **截图兜底**：个别无控件树的 App，退化为截图 + 视觉模型 OCR。
- **节奏像人**：滚动/翻页放缓，避免触发风控。

## 适配新 App 的步骤

1. 先**只读**验证：启动 → 截图 → 取 `/source` 看控件树是否够用
2. 确认 App 分级（见 [../../docs/app-tiers.md](../../docs/app-tiers.md)）：内容消费类放心做，电商只读，金融不做
3. 写该 App 的"卡片解析"：定位 标题/作者/互动数 在控件树里的规律
4. 复用本目录的滚动+去重+排序框架
